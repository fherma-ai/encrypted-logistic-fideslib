# Logistic over CKKS on the GPU — a Chebyshev series to T₇₇, with FIDESlib

> **A port to [FIDESlib](https://github.com/CAPS-UMU/FIDESlib), by the FHERMA
> team.** The circuit is the LogisticFunction component of [polycircuit](https://github.com/fairmath/polycircuit) (Apache-2.0) — the winning approach of the FHERMA Logistic Function challenge, by [Aikata](https://www.iaik.tugraz.at/person/aikata-aikata/) (TU Graz) — moved
> operation for operation onto FIDESlib's device ciphertexts. The mathematics
> is the original author's, untouched; what is ours is the plumbing to the
> card. Answers [`logistic` / `f64@1.0.0`](https://fherma.io/kernels/logistic) on the
> FHERMA kernel catalogue, beside the CPU answer it is a port of:
> [fherma-ai/encrypted-logistic-ckks](https://github.com/fherma-ai/encrypted-logistic-ckks).

σ(x) = 1/(1+e⁻ˣ) for every element of an encrypted vector, x ∈ [−25, 25]: OpenFHE's Chebyshev series to the 59th coefficient, with the odd terms unrolled by hand to T₇₇ through the product formula, in seven levels. 99.9988% within 1e-3.

```text
kernel logistic<N: u32>(
    %xs: secret<tensor<N x f64>>,
) -> %y: secret<tensor<N x f64>>
```

## What is measured, and what the two rows differ by

Same specification, same testing bundle, same parameters as the CPU answer
(`config.jsonc` is its copy: ring 2¹⁵, depth 7, 2048 slots, 50-bit scale, 128-bit classical). The platform's envelope makes
the context, the keys and the ciphertexts with OpenFHE before the clock
starts; `solve_run` hands the ciphertext to FIDESlib's OpenFHE interop layer,
runs the circuit on the card and returns an OpenFHE ciphertext the envelope
decrypts. The trip to the card and back is inside the measurement, because it
is part of what answering on a GPU costs. So what separates the two rows on
the board is the machine and the library.

| | |
| --- | --- |
| [`solution/gpu.cu`](solution/gpu.cu) | the device context adapted from the envelope's, the relinearisation key onto the card, and the circuit — compiled by nvcc |
| [`solution/solve.cpp`](solution/solve.cpp) | how the vector is packed and read back — plain C++, as in the CPU answer |
| [`solution/config.jsonc`](solution/config.jsonc) | the context parameters, the CPU answer's |
| [`solution/CMakeLists.txt`](solution/CMakeLists.txt) | C++ and CUDA in one target, linked against `fideslib::fideslib` |
| `solution/main.cpp`, `envelope.h`, `fherma.h`, `solve.h` | generated by the platform from the signature; laid over the clone afresh at every measurement |

## Running it

Inside the `fherma/fideslib` image, on a machine with an NVIDIA GPU (CUDA
12.8 or later; compiled for the L40S and the RTX PRO 6000 Blackwell):

```sh
cd solution
docker run --rm --gpus all -v "$PWD":/solution -w /solution fherma/fideslib:2.1.3 \
    sh -c "cmake -B build -DCMAKE_BUILD_TYPE=Release && cmake --build build -j && ./build/solution <point-dir>"
```
